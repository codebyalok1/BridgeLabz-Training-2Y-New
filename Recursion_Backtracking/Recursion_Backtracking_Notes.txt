Module 1: Introduction to Recursion
1.1 What is Recursion?
Recursion is a programming technique where a function calls itself directly or indirectly to solve
a problem by breaking it down into smaller, similar subproblems. Each recursive call works on a
simpler version of the original problem until a base condition is met.
Mathematical Definition: A recursive function f(n) can be defined as:
● f(n) = base value, if n satisfies base condition
● f(n) = some operation involving f(n-1) or f(smaller problem), otherwise
Real-world Analogies:
● Russian nesting dolls (Matryoshka): Each doll contains a smaller version of itself
● Mirrors facing each other: Creating infinite reflections
● Searching for a file in nested folders
● Company organizational hierarchy
● Family genealogy tree
1.2 Why Use Recursion?
Advantages:
● Provides elegant and simple solutions for naturally recursive problems
● Reduces code complexity for problems like tree traversal, graph algorithms
● Makes code more readable and maintainable for certain problems
● Essential for divide-and-conquer algorithms
Appropriate Use Cases:
● Tree and graph traversals
● Divide and conquer algorithms (merge sort, quick sort)
● Backtracking problems (N-Queens, Sudoku)
● Mathematical computations (factorial, fibonacci)
● Dynamic programming problems

Module 2: Recursive Function Structure
2.1 Components of a Recursive Function
Every recursive function must have two essential components:
2.1.1 Base Case (Termination Condition)

The base case is the condition that stops the recursion. It provides a direct answer without
making further recursive calls.
Importance:
● Prevents infinite recursion
● Acts as the stopping criterion
● Usually handles the simplest instance of the problem
● Must be reachable from any recursive call
Example: In calculating factorial:
● Base case: if n == 0 or n == 1, return 1
● This is the simplest case where we know the answer directly
2.1.2 Recursive Case
The recursive case is where the function calls itself with a modified argument, moving toward
the base case.
Characteristics:
● Breaks down the problem into smaller subproblems
● Each call should progress toward the base case
● Combines results from recursive calls
● Must ensure the problem size decreases
Example: In calculating factorial:
● Recursive case: return n × factorial(n-1)
● Problem size decreases from n to n-1
2.2 General Recursive Function Template
function recursiveFunction(parameters):
// Base Case(s)
if (base condition is met):
return base value
// Recursive Case
// 1. Process current level (if needed)
// 2. Make recursive call(s) with smaller problem
// 3. Combine results (if needed)
result = recursiveFunction(modified parameters)
return processed result

2.6 Example 4: Power Function
Problem: Calculate x^n (x raised to power n)
Recursive Definition:
● power(x, 0) = 1 (base case)
● power(x, n) = x × power(x, n-1) (recursive case)
Optimized Version (Divide and Conquer):
● power(x, n) = power(x, n/2) × power(x, n/2) if n is even
● power(x, n) = x × power(x, n-1) if n is odd
Example: power(2, 4)
Naive Approach: O(n)
power(2, 4) = 2 × power(2, 3)
= 2 × 2 × power(2, 2)
= 2 × 2 × 2 × power(2, 1)
= 2 × 2 × 2 × 2 × power(2, 0)
= 2 × 2 × 2 × 2 × 1 = 16

Optimized Approach: O(log n)
power(2, 4) = power(2, 2) × power(2, 2)

= [power(2, 1) × power(2, 1)] × [power(2, 1) × power(2,

1)]

= [2 × 2] × [2 × 2]
= 4 × 4 = 16

2.7 How Recursion Works: The Call Stack
The call stack is a data structure that stores information about active function calls. When a
function is called, a new frame is pushed onto the stack containing:

● Local variables
● Parameters
● Return address
Stack Operations:
1. Push: When a recursive call is made
2. Pop: When a function returns
Memory Considerations:
● Each recursive call consumes stack space
● Too many recursive calls can cause stack overflow
● Tail recursion optimization can help in some languages

3.1 Comparison Table

3.2 Example Comparison: Factorial
Recursive Implementation:
Pseudocode:
function factorial(n):
if n <= 1:
return 1
return n * factorial(n - 1)
Time Complexity: O(n)

Space Complexity: O(n) due to call stack
Iterative Implementation:
Pseudocode:
function factorial(n):
result = 1
for i from 2 to n:
result = result * i
return result
Time Complexity: O(n)
Space Complexity: O(1)

3.3 Example Comparison: Fibonacci
Recursive Implementation (Naive):
Pseudocode:
function fibonacci(n):
if n <= 1:
return n
return fibonacci(n-1) + fibonacci(n-2)
Time Complexity: O(2^n) - exponential
Space Complexity: O(n) - maximum call stack depth
Problems: Massive redundant calculations
Iterative Implementation:
Pseudocode:
function fibonacci(n):
if n <= 1:
return n
prev = 0, curr = 1
for i from 2 to n:
next = prev + curr
prev = curr
curr = next
return curr
Time Complexity: O(n)
Space Complexity: O(1)

3.4 When to Use Recursion vs. Iteration
Use Recursion When:
● Problem has a natural recursive structure (trees, graphs)
● Code simplicity and readability are priorities

● Stack depth won’t be excessive
● Implementing divide-and-conquer algorithms
● Working with backtracking problems
Use Iteration When:
● Performance is critical
● Memory is limited
● Problem is naturally sequential
● Stack overflow is a concern
● Simple counting or accumulation is needed
Problems Better Suited for Recursion:
● Tree traversals
● Graph algorithms (DFS)
● Tower of Hanoi
● Backtracking problems
● Divide and conquer algorithms
Problems Better Suited for Iteration:
● Simple loops and counters
● Array processing
● String manipulation
● Mathematical calculations with fixed iterations
3.5 Converting Recursion to Iteration
Most recursive algorithms can be converted to iterative ones using explicit stacks or loops.
Example: Binary Tree Inorder Traversal
Recursive:
function inorder(node):
if node is null:
return
inorder(node.left)
print(node.data)
inorder(node.right)
Iterative (using explicit stack):
function inorder(root):
stack = empty stack
current = root
while current is not null OR stack is not empty:
while current is not null:
push current to stack
current = current.left
current = pop from stack
print(current.data)
current = current.right

Module 4: Introduction to Backtracking
4.1 What is Backtracking?
Backtracking is an algorithmic technique that incrementally builds candidates for solutions and
abandons a candidate (“backtracks”) as soon as it determines that the candidate cannot lead to
a valid solution.
Key Concept: “Try, and if it doesn’t work, undo and try something else.”
Characteristics:
● Systematic way to explore all possible solutions
● Uses recursion to explore solution space
● Prunes branches that cannot lead to solutions
● Memory efficient compared to storing all possibilities
Real-world Analogies:
● Finding your way out of a maze (try a path, if dead-end, backtrack)
● Solving a Sudoku puzzle (place a number, if conflict arises, undo and try another)
● Chess game planning (try a move, evaluate, undo if bad)
4.2 Backtracking vs. Brute Force
Brute Force:
● Explores every possible solution
● No pruning of search space
● Very inefficient for large problems
Backtracking:
● Explores solutions intelligently
● Prunes invalid branches early
● More efficient than brute force
● Still exponential in worst case, but practically faster
4.3 Types of Backtracking Problems
Decision Problems: Find a feasible solution
● Example: Does a solution exist for this Sudoku?
Optimization Problems: Find the best solution
● Example: Find the shortest Hamiltonian path
Enumeration Problems: Find all solutions
● Example: Find all valid N-Queens configurations

Module 5: General Backtracking Template

5.1 The Backtracking Algorithm Structure
function backtrack(state, choices):
// Base Case: Solution found or dead end
if is_solution(state):
process_solution(state)
return
if is_dead_end(state):
return
// Recursive Case: Explore all choices
for each choice in get_valid_choices(state):
// Make choice
make_choice(state, choice)
// Recurse
backtrack(state, remaining_choices)
// Undo choice (backtrack)
undo_choice(state, choice)

5.2 Key Components Explained
1. State: Current configuration or partial solution being built
2. Choices: Possible decisions that can be made at current state
3. Constraints: Rules that determine valid choices
4. Goal: Condition that defines a complete solution
5. Make Choice: Modify state to include current choice
6. Recurse: Explore further with the modified state
7. Undo Choice: Restore state to try other alternatives
5.3 Example: Generating All Permutations
Problem: Generate all permutations of the string “ABC”
Expected Output: ABC, ACB, BAC, BCA, CAB, CBA
Backtracking Approach:
State: Current permutation being built
Choices: Remaining unused characters
Constraint: Each character used only once
Goal: All characters used
Algorithm:
function permute(chosen, remaining):
// Base case: no more characters to add
if remaining is empty:

print(chosen)
return
// Try each remaining character
for each char in remaining:
// Make choice
add char to chosen
remove char from remaining
// Recurse
permute(chosen, remaining)
// Undo choice
remove char from chosen
add char back to remaining

function subsetSum(numbers, target, index, currentSum, solution):

if currentSum == target:
print(solution)

return true
// Base case: exceeded target or no more numbers

return false

remove numbers[index] from solution // backtrack

return true
return false

Module 6: Solving the N-Queens Problem
6.1 Problem Statement
The N-Queens Problem: Place N chess queens on an N×N chessboard such that no two
queens threaten each other. This means:
● No two queens share the same row
● No two queens share the same column
● No two queens share the same diagonal
Example for N=4:
Valid Solution:
. Q . .

. . . Q
Q . . .
. . Q .
Invalid (Queens attack each other):
Q Q . .
. . Q .
. . . Q
. Q . .

6.2 Problem Analysis
Search Space:
● Brute force: N^N possible ways to place N queens
● With constraint (one queen per row): N! possibilities
● Backtracking significantly reduces this
Constraints:
1. Exactly one queen per row
2. Exactly one queen per column
3. At most one queen per diagonal
Key Insight: Place one queen per row, checking column and diagonal conflicts
6.3 N-Queens Backtracking Algorithm
function solveNQueens(n):
board = create n×n board initialized with 0
solutions = empty list
solveNQueensUtil(board, 0, n, solutions)
return solutions
function solveNQueensUtil(board, row, n, solutions):
// Base case: all queens placed
if row >= n:
add current board to solutions
return
// Try placing queen in each column of current row
for col from 0 to n-1:
if isSafe(board, row, col, n):
// Make choice
board[row][col] = 1
// Recurse to place next queen
solveNQueensUtil(board, row+1, n, solutions)
// Backtrack
board[row][col] = 0

function isSafe(board, row, col, n):
// Check column
for i from 0 to row-1:
if board[i][col] == 1:
return false

// Check upper-left diagonal
i = row - 1
j = col - 1
while i >= 0 AND j >= 0:
if board[i][j] == 1:
return false
i = i - 1
j = j - 1
// Check upper-right diagonal
i = row - 1
j = col + 1
while i >= 0 AND j < n:
if board[i][j] == 1:
return false
i = i - 1
j = j + 1
return true

6.6 Complexity Analysis
Time Complexity: O(N!)
● For each row, we try N columns
● But many branches are pruned early
● Much better than O(N^N) brute force
Space Complexity: O(N2)
● Board storage: O(N2)
● Recursion stack: O(N)
Number of Solutions for Different N:
● N=1: 1 solution
● N=4: 2 solutions
● N=8: 92 solutions
● N=10: 724 solutions
6.7 Optimizations
1. Using Arrays Instead of 2D Board:
Use 1D array where index = row, value = column
board = [1, 3, 0, 2] represents:
Row 0: Queen at column 1
Row 1: Queen at column 3
Row 2: Queen at column 0
Row 3: Queen at column 2
2. Efficient Diagonal Checking:
For position (row, col):
- Left diagonal: row - col is constant

- Right diagonal: row + col is constant
Use boolean arrays to mark occupied diagonals
3. Bitwise Operations: Use bit manipulation for faster checking of columns and diagonals.
6.8 Variations and Extensions
1. Count total solutions instead of finding all
2. Find first solution only (stop after finding one)
3. N-Queens with obstacles: Some squares are blocked
4. Print all unique solutions (considering rotations and reflections as same)

Module 7: Common Backtracking Problems
7.1 Sudoku Solver
Problem: Fill a 9×9 grid with digits 1-9 such that each row, column, and 3×3 box contains each
digit exactly once.
Backtracking Strategy:
● Find empty cell
● Try digits 1-9
● Check if digit is valid (row, column, box constraints)
● Place digit and recurse
● If no solution found, backtrack and try next digit
7.2 Rat in a Maze
Problem: Find path from top-left to bottom-right in a maze with obstacles.
Backtracking Strategy:
● Try moving in all valid directions (up, down, left, right)
● Mark current cell as part of path
● Recursively explore from new position
● If dead end, backtrack and try different direction
7.3 Word Search in Grid
Problem: Find if a word exists in a 2D grid by moving horizontally or vertically.
Backtracking Strategy:
● Start from each cell matching first character
● Recursively search adjacent cells for next character
● Mark visited cells
● Backtrack if path doesn’t lead to solution

7.4 Graph Coloring
Problem: Color graph vertices such that no two adjacent vertices have same color, using
minimum colors.
Backtracking Strategy:
● Assign colors to vertices one by one
● Check if current color assignment is valid
● Try all colors for current vertex
● Backtrack if no valid coloring found

Summary and Key Takeaways
Recursion is a powerful technique where problems are solved by breaking them into smaller
instances of the same problem. Every recursive solution must have well-defined base cases
and recursive cases that progress toward those base cases.
Recursion vs. Iteration involves tradeoffs between code elegance and performance. Recursive
solutions are often more intuitive for naturally recursive problems (trees, backtracking) but
consume more memory and risk stack overflow. Iterative solutions are generally more efficient
but may be harder to conceptualize for certain problems.
Backtracking is an algorithmic paradigm that systematically explores the solution space by
building candidates incrementally and abandoning them when they cannot lead to valid
solutions. It’s essentially an optimized brute force approach that prunes invalid branches early.
The General Backtracking Template consists of making a choice, recursively exploring that
choice, and undoing the choice (backtracking) if it doesn’t lead to a solution. This pattern applies
to numerous problems including N-Queens, Sudoku, maze solving, and constraint satisfaction
problems.
The N-Queens Problem exemplifies backtracking by placing queens row-by-row and checking
constraints (column and diagonal attacks) before proceeding. It demonstrates how backtracking
can solve problems with large search spaces efficiently by pruning invalid branches early.
Real-world Applications: Recursion and backtracking power many real-world systems
including compilers (parsing), AI game playing (decision trees), scheduling systems, puzzle
solvers, path finding algorithms, and optimization problems. Understanding these concepts is
fundamental for solving complex computational problems efficiently.
Practical Considerations: When implementing recursive or backtracking solutions, always
consider stack depth limitations, optimization opportunities (memoization, pruning), and whether
an iterative solution might be more appropriate for production systems.
